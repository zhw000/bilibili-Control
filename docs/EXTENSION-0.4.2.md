# Chrome 扩展 0.4.2：重新加载后的旧脚本清理

包含 0.4.1 的手动播放、全屏退出修复。仅需更新 Chrome 扩展，现有电脑助手和 iPhone App 无需更新。

## 问题与修复

重新加载扩展后，已经打开的网页可能仍运行旧内容脚本。其扩展上下文失效，`chrome.runtime.sendMessage` 会同步抛出 `Extension context invalidated`；旧代码只处理 Promise 拒绝，因此每秒状态上报会不断产生未捕获异常。

0.4.2 同时处理同步异常、异步拒绝和失效的 runtime。确认失效后停止上报定时器、移除旧事件监听、恢复被队列临时修改的连播开关，并取消等待中的播放及全屏操作。普通的后台暂时未连接不会触发永久清理。异步操作结束时，也不再向失效的响应通道回传消息。

## 更新与恢复

1. 将 `BiliRemote-Chrome-0.4.2.zip` 解压并覆盖 Chrome 当前加载的扩展目录。
2. 在 `chrome://extensions` 重新加载“哔哩遥控 · Bili Remote”，确认版本为 **0.4.2**。
3. **刷新所有已打开的 B 站页面**，包括视频、搜索和 UP 主页面，或关闭后重新打开。这一步会移除更新前已注入的旧脚本；仅重新加载扩展不能替换它们。
4. 扩展错误页中此前记录的错误可以清空，再观察是否有新错误。

如果只想立即恢复当前页面，先刷新报错对应的 B 站标签页即可。

## 验证

类型检查和 79 项自动化测试通过。新增回归覆盖同步抛错、异步拒绝、runtime ID 消失、runtime 访问抛错、首次通知失败、释放连播控制权、取消加载中的播放、失效响应通道以及待执行的 Esc 退出清理。更新包已本地构建；未在用户浏览器中重新加载扩展进行现场验收。
